# Pocket Phone

Native Android dashboard and compact apps for the Nothing Phone (3a). Version 0.5.16 runs on Android 6 and newer, including the existing Nothing OS installation. It is currently a launcher/app component; no full ROM image has been compiled or verified for daily use.

Version 0.5.16 adds native chat alongside the home dashboard. Swipe left across the right half of Home, Today or Tools, away from the screen edges, or tap Chat in the Home or Today footer. Back closes the sidebar. Replies stream directly from the selected provider on the phone, with Stop/Retry, Markdown and local history. No PC is required. Only the conversation you enter is sent; Pocket does not automatically attach notes, tasks or photos. Chat history and drafts stay on the phone and are excluded from Drive sync. An installable update still needs the existing release signing key.

Chat → ⋮ → Provider & model supports Anthropic through its Java SDK, or a provider's OpenAI-compatible HTTPS chat-completions endpoint. Enter its model ID, API base URL and API key. Anthropic shares Journal's encrypted key storage; other keys are encrypted separately and bound to their exact endpoint. Switching provider, model or endpoint asks before clearing the current conversation. API access uses the provider's billing; [Claude subscriptions do not include direct API usage](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console).

The default reply limit is 2,048 tokens; lower it in Chat settings or choose a less expensive model. Anthropic prompt caching is on by default, using five-minute automatic cache breakpoints as the conversation grows. [Cache writes cost extra; reusing a sufficiently long prefix makes later input cheaper](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Generated output still costs money. Other providers manage caching according to their own API; Pocket shows cache hits only when the provider reports them. It does not pad prompts, prewarm caches or automatically retry paid requests. Response-only APIs and nonstandard authentication are not supported by the compatible adapter.

The phone's task list now uses larger readable titles, native checkboxes, clearer due dates and a visible action menu. Task details edit dates and importance directly and support adding/checking steps. Save stays in the editor header. Optional Drive sync now includes tasks, checklist progress and the chosen next task; reminders and drafts remain on the phone.

Journal photos wait locally until a reading key is set. Cloud sync and journal transcription are separately opt-in; the APK now includes Internet and network-state permissions. See [USE-POCKET-0.5.14.md](USE-POCKET-0.5.14.md) for the update and [CLOUD.md](CLOUD.md) for account setup.

Messages puts the active feed first and moves SMS/app navigation into two bottom commands. Phone number entry is larger and its plus key respects the cursor. The terminal palette, compact headers, native gestures and settings behind each app's Settings button are retained. See [APP-STATUS.md](APP-STATUS.md) for everyday scope and remaining limits.

Version 0.5.12 changes Today’s information hierarchy: a centered date, one current/next appointment as a borderless focus block, + Task / Note / Focus commands, task tabs/list, then Notes. Today and Agenda use one monospace typeface with size, weight and brightness for hierarchy. Task group headings appear only when there are multiple groups. Search opens a real command-style field on request; Calendar is separate navigation at the bottom. Focus uses the shown appointment’s title and keeps it across recreation. Version 0.5.5 is an incremental reliability update. Alarm records migrate to device-protected storage for reboot-before-unlock scheduling; ringing uses an asynchronously prepared tone, a bundled fallback, optional vibration, occurrence-specific Stop/Snooze controls and a bounded foreground service. Clock → Alarm setup / test shows access/channel/volume status and offers a real ten-second test. Camera opening/configuration has timeouts; an explicit photo save uses a short foreground service while Home is visible. Phone guards repeated call taps and uses the supported proximity wake lock while talking through the earpiece. Delayed reads and permission callbacks cannot change an abandoned page; accepted contact/appointment writes run once in a shared ordered worker and finish across activity destruction. Notes autosave drafts after a short pause, retain intentionally empty drafts and accept newly shared text in an open editor. Calendar retry markers and revision-aware results preserve newer local edits. See [RELEASES.md](RELEASES.md) for this increment and the next checks.

In 0.5.4, internal navigation uses short native property animations over a stable window host. Android 14+ Back gestures reveal an already visited parent page, follow finger progress, return cleanly on cancellation and preserve the editor. Scroll positions restore after provider data arrives and survive recreation. Motion follows Android's animator setting; Settings → Motion → Off disables Pocket transitions. Old photo views are removed before their bitmaps are recycled. Visual history is bounded to three pages and cleared when the activity stops.

Own app launches reuse the current task and supply Android launch-origin options where available. Phone history, Files' open photo and Clock's timer editor retain their view on a plain reopening; Home intents update the grid without rebuilding it. Messages and Files refresh unchanged data in place. App enumeration, label loading and sorting happen in a worker; search uses cached labels and rows populate in batches of 24 per frame. The today tile opens Pocket Today as a separate task, so an open organizer editor can remain in Recents while Home shows the dashboard. System Home/Recents animations and the display refresh policy remain Android/Nothing OS controls; this APK does not implement a privileged overview service.

In 0.5.3, SMS sending uses a snapshot of the tapped message: navigating back, changing the recipient or opening another conversation cannot clear an unrelated editor or switch it back. New text and unsent drafts remain saved. The send control stays disabled during permission/SIM selection and the provider/carrier handoff; cancellation or failure releases it without an automatic retry. Thread lookup happens before sending, so a failed lookup after an accepted SMS cannot produce a misleading retry. Reopening a pending conversation and stopping after handoff do not re-save the sent draft. Permission-return handling preserves the typed recipient and resets its old thread.

In 0.5.2, Files opens **only Pocket Camera photos**, using native media ownership on Android 10+ and a private capture index on older Android. Previous file/folder grants are released; no file/folder picker or general photo-library access is used by Files. SMS setup follows Android's default-SMS role and read permission, then refreshes after returning from settings. Notification setup opens Android's actual listener consent screen, distinguishes off/waiting/connected states and explains the manual restricted-settings step for a sideloaded APK.

Notification badges and footer controls have larger touch targets; notification Open/Reply/More buttons are 56 dp tall. Today has due dates, Important, subtasks/progress, Open/Today/Later/Done filters and text search. Tap a task title for details; its separate checkbox completes it. Notes store ordinary Markdown and use [Markwon](https://github.com/noties/Markwon) for native previews. The editor adds a Task action to capture the current note without changing its draft. Their editor expands into the available window height; in short windows the controls remain scrollable. Hold inside the editor to open a formatting wheel, or tap Format. Move to a format and release, or release first and tap. More opens all styles, and Select opens Android text selection and clipboard actions. Android's system gestures remain available.

For everyday Home use, retain the phone's current Phone and Messages defaults while testing Pocket. Hold those dashboard tiles to assign the already installed apps. Turning Pocket into the default dialer/SMS handler is optional and needs real calls/messages to verify it. Keep the stock clock for essential alarms until Pocket has been checked with the screen off, after reboot and overnight on the handset.

The `rom` edition has nine default tiles: phone, messages, contacts, clock, camera, calculator, files, today and settings. Each opens Pocket's own native interface. Hold a tile to assign another installed app. Black backgrounds, white text/icons, a pale-yellow accent, VT323 headings and short menus carry the same style across the apps. The `debug` and `release` editions retain the earlier optional-app grid.

Home displays the actual time/date, next local task, unfinished task count and Android's next alarm. Direct task/note capture and focus controls sit above the grid. Name and T9-number search help find installed apps; D-pad and physical/Bluetooth number keys 1–9 select Home tiles. There are no preloaded tasks, contacts, messages or appointments.

Phone has its own dial pad, call history and incoming/active-call controls. Messages shows active messaging notifications, native conversation opening and user-initiated notification replies; its SMS inbox has conversations, drafts, multipart send results and received MMS. Contacts reads and edits Android's address book. Clock supplies exact alarms, daily alarms, multiple timers, pause/resume, snooze and a stopwatch. Calculator evaluates bounded decimal arithmetic. Files supplies the read-only Pocket Camera album, Previous/Next navigation and photo sharing. Received MMS attachments have their own viewer inside Messages. Today contains local tasks with deadlines, priority and subtasks, Markdown notes, drafts, sharing/export and links to Pocket's Agenda and focus timers. Device settings offers brightness, volume and Do Not Disturb controls, with Android panels for protected settings. See [APPS.md](APPS.md) for the actual scope, permissions and remaining handset checks.

Android provides telephony, native data providers, alarm scheduling, camera capture and system permissions. Standard Android screens still choose default apps, grant access, choose export destinations and change protected networking/security settings. Pocket Phone and the SMS inbox must be selected as the relevant default apps before Pocket can operate the carrier call/SMS services. WhatsApp notification reading does not require the default-SMS role. Emergency calls use the system dialer.

Android keeps control of bottom-edge Home and Recents gestures. Pocket app activities use separate tasks; the launcher does not intercept upward swipes or exclude system gesture areas. Newer Android versions also provide predictive Back callbacks for internal pages. Physical smoothness and Nothing OS transitions still require testing on the phone.

Agenda optionally uses a writable Google calendar already synchronized on the phone through Android's Calendar Provider. Choose it explicitly in Agenda → Settings after granting calendar access. Android's account sync handles the transfer; the calendar link itself uses no Pocket login. Tasks and notes leave the phone only with the optional cloud sync below, and Pocket appointment reminders remain local alarms. This does not connect Google Keep or Google Tasks.

Notification access is optional and shows other apps' current notifications, including app-provided Open and Reply actions. Received notification text is not automatically archived. An explicit **More → Make task** action saves only the source snapshot the user chose, attached to that task. Only the user's unfinished reply is stored privately, for up to seven days or until submission. Android may block this sensitive setting for a sideloaded APK. Open Messages or Notifications → Settings for setup. The setup screen links to app info; if Android offers **⋮ → Allow restricted settings**, the user must approve it there, then enable Notification access. The app cannot grant or bypass it. Leave it disabled if you do not want that access. Pocket's own SMS and alarm alerts use the separate notification permission. Calendar account sync and SMS/MMS transfers use Android's services separately from Pocket's optional cloud sync.

The built-in [camera](CAMERA.md) uses Camera2 preview and YUV capture, native autofocus/auto exposure and available hardware flash. Six independently designed early-digital profiles are applied before one JPEG encode. Photos save to `DCIM/Pocket` and open in Pocket Files. The profiles approximate broad camera-family characteristics; they are not measured manufacturer emulations.

## Cloud sync and web

Optional cloud sync copies tasks, Parking Lot, Receipt, Dice lists, notes and journal pages to a hidden app folder in your own Google Drive and syncs again whenever the phone is back online. It is off until you turn it on in Settings → Cloud sync; for this the APK now declares the `INTERNET` permission. The web workstation reads the shared Pocket documents from [`docs/`](docs/) via GitHub Pages; task controls are native on the phone. Journal turns photos of paper journal pages into notes with Claude (your own API key, about 1–2¢ per page), on the phone or on demand in the web page, while keeping the photo behind every line. See [CLOUD.md](CLOUD.md) for the merge rule, the journal and the one-time Google setup.

## Downloads

Signed incremental APKs are available in [GitHub Releases](https://github.com/alsanatilla/pocket-phone/releases). Install the APK over the existing Pocket Phone app to retain local data. See [USE-POCKET-0.5.14.md](USE-POCKET-0.5.14.md) for installation and setup.

Each release links its signed APK, source archive, checksum manifest and build status. Downloads stored on `release-files` pin the verified file commit. Signing keys and local SDK settings are excluded from this repository.

## Build and verify

Use JDK 17 and Android SDK 35. Set the SDK path in an untracked `local.properties`, or open the project in Android Studio.

```sh
./gradlew :app:assembleRom :app:lintRom :app:testRomUnitTest :app:testDebugUnitTest
```

The unsigned ROM prebuilt is `app/build/outputs/apk/rom/app-rom-unsigned.apk`; the Android ROM build signs it. The supplied signed APK updates the earlier Pocket Phone previews while retaining local app data. It runs on the current OS; a full ROM image has not been compiled.

Automated tests exercise native provider operations, multipart SMS state, concurrent compose/navigation/permission/SIM flows, MMS storage/failure cleanup, contacts, calendar writes, exact timer scheduling, Camera-only album ownership and migration, real notification connection/dismissal, SMS role/access return handling, task metadata migration and draft persistence, Markdown selection/continuation/preview, touch target sizes, permission status, arithmetic, navigation intents and camera processing/storage. Native Android UI rendering tests write screenshots to `app/build/screenshots`; their sample data is not included in the APK. Live cellular calls, carrier SMS/MMS delivery, Google account synchronization, hardware controls, overnight alarms and gesture animations remain unverified on the Nothing Phone (3a). The download's `BUILD-STATUS.json` records the latest check counts and outstanding device work.

For the companion-app and Today/Agenda PNG fixtures, use `./gradlew -I tools/render-layouts.gradle :app:renderRomLayouts` after the full checks. This runs the native API 28 render fixtures in their own JVM and writes a separate test report, retaining the full-suite reports. Running many SDK sandboxes in the same Robolectric JVM can leave native text rendering caches incomplete; the isolated previews are the review artifacts. They are not physical handset recordings.

To render one fixture in a fresh JVM, add `-PrenderCase=org.textphone.launcher.DailyPolishPreviewTest.messageFeedComesFirstAndTransportCommandsStayAtTheBottom`. Select complete reviewed renderings for release previews; native font caches can omit repeated static text across unrelated fixture screens. This is a renderer limitation, not handset validation.
