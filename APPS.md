## Connected productivity

Home's next-task row opens that exact task’s details, and the next appointment appears beneath it. Today shows one current/next appointment above the task list. An ongoing timed event takes priority over an all-day entry. Open the bottom Calendar button for the full Agenda. Due/overdue dates remain visible on individual tasks. Google events come from the explicitly selected calendar already synchronized on the phone. Tap a task title to open its details; tap its separate 56 dp checkbox to complete/reopen it. Details show subtask progress, edit, Make next, focus and Schedule reminder. Due dates follow the phone's local calendar and do not silently create alerts. Today includes overdue work, Later shows future deadlines, and Open includes undated tasks. Important sorts within a due date; an explicit Make next overrides Home's default deadline/priority order. Existing entries are migrated without changing IDs or saved text. Hold a task and choose Schedule, or use Schedule reminder in its details, to open the task’s dedicated reminder editor. It saves one exact, one-shot alarm; editing its time reuses the alarm ID. Snoozing retains the task link. Completing/deleting a task cancels its linked reminders, including a linked appointment’s alarm, while retaining the appointment itself. Reopening a completed task does not restore old reminders. Agenda can create/edit/delete local appointments and request a local alarm at the appointment time. A task link opens that task's details in Today, and Back returns to the previous task/list screen. Focus starts a 25/50-minute timer or five-minute break in Pocket Clock, titled with the next task. Completing a task does not delete its appointment or cancel an unrelated focus timer. Task recurrence is not implemented. Appointment duration is editable; the alarm still rings at the chosen start.

Pin saved notes from their hold menu or Preview → More; pinned notes appear first and show Pinned metadata. Pinning does not alter Markdown or another draft. Notes keep literal Markdown. Hold inside the editor for Heading, Bullets, Checks, Bold, Plain, Undo, Select and More. Move to a choice and release, or release first and tap. Heading cycles H1/H2/H3. Tap Format for the same wheel. More exposes every heading level, numbered lists, quotes, wheel help and confirmed Clear draft. Select opens Android selection/clipboard actions. Short windows use the full menu rather than shrinking targets. The editor and Preview have a Task action that opens a separate source capture; the note’s current draft is preserved. Bold works on the selection. Enter continues lists and ends an empty list. Undo can revert formatting while the document still matches that operation; later typing is never discarded by formatting undo. Clear draft requires confirmation and preserves the saved note. Preview uses Markwon core, task-list and strikethrough extensions, with native selectable text and compact Edit/Share/Task actions. It does not underline H1/H2 automatically. No image-download, HTML, WebView or network plugins are included. Share/export retain Markdown source; export creates `pocket-notes.md` through Android's file picker. Draft text, task date/priority/steps and note cursor selection survive leaving/recreation.

Share text or a link from another app to **Pocket Phone** to open an unsaved note draft. **Pocket Messages** is a separate plain-text Share destination and prepares an unsent SMS. Saving or sending always needs a user action. Photos open in the own Files viewer. Contacts opens the own dial pad or SMS composer.

A source capture starts from **Notes → Task**, a message/notification’s **More → Make task**, or Android’s **Share → Pocket Task**. It retains the original note reference, the selected notice identity/app and text, or shared text/link. Task Source opens the original when available, otherwise its saved snapshot. It does not grant access to the rest of the source app. Markdown export includes the attached source text. The main note/task editor’s draft is independent. Up to 20 unfinished source captures are retained until saved or explicitly discarded; Today → Settings → Task drafts resumes or discards them. Saving twice or recreating an accepted capture cannot create a duplicate task. A reminder failure preserves the accepted task and shows a retry path.

## Google Calendar

Open **today → Calendar → Connect Google Calendar**. Grant calendar access and select a writable Google calendar already present on this phone. If no calendar appears, configure Google Calendar/account synchronization in Android first. New Pocket appointments are written to that calendar, and Android's account sync can transfer them. **Sync Pocket appointments** explicitly copies existing local entries and retries pending writes. If a provider write fails, the local appointment remains saved with a retry option.

Agenda groups appointments under readable day headings with separate time and title columns, Upcoming/Past filters, and local/synced status. Back keeps an unfinished appointment separately from the saved event; Continue draft reopens it without creating an alarm. One appointment draft is retained at a time. The selected calendar supplies the coming 90 days and the previous 90 days in Past. External/recurring Google events can be viewed and turned into a local task. Pocket-created calendar copies can be edited or explicitly deleted from both places. Disconnecting stops subsequent provider writes; it does not remove existing Google events. Existing event copies retain their original calendar when another calendar is selected.

When an external calendar copy changes, Agenda displays that changed event once and offers Open in calendar. Pending local changes take precedence. Remote changes are not yet fully reconciled into the saved local record, and deletions/conflicts still need a complete reconciliation workflow. Pocket appointment duration is editable from 1 to 1440 minutes; existing records default to 60 minutes. The selected duration determines the end written to Android CalendarProvider. Pocket reminder alarms are local and are not written as Google reminder rules. Notes/tasks do not sync to Google Keep or Google Tasks. No live account has been connected or accessed from the build environment. The minimal ROM source profile does not bundle Google Play services or a Google sync adapter, so it cannot supply this account sync by itself.

## Navigation

Enable gesture navigation in Android's settings. A short bottom-edge swipe goes Home; swipe up and hold opens Android Recents. Pocket does not install a custom gesture service or intercept these gestures. The custom phone, messages, contacts, clock, camera, calculator, files, agenda and device-settings screens have separate task affinities and are launched with `NEW_TASK`. Returning Home preserves their running task and drafts. The today tile opens an independent Pocket Today task; direct Home capture, its linked organizer pages and launcher preferences remain in the Home task. The Notes editor grows to use the available height, with scrollable controls in short windows. Protected Android dialogs/panels follow the normal platform navigation.

Internal Back follows a bounded, restored route history in Home/Today: a note opened from Home returns there; Preview returns to its editor; task edit returns to its details. Header Back and Android Back share that behavior. Saving commits the entry and returns to the origin without leaving a discarded editor in history. Clock returns to the previously visited tab; editing an existing contact returns to its detail. Messages opens its SMS inbox and reply editor in its current task, so native Back returns to the hub. Internal pages support Android's Back callback on Android 13+ and a progress/cancel animation on Android 14+. Root app screens use the platform's normal Back-to-Home behavior. Gesture animation timing and the stock Nothing OS Recents appearance have not been measured on the handset.

## Access and stored data

Pocket asks for permissions as relevant features are used. Settings → **Permissions** shows purpose and current state, with controls for Android's app permissions, default apps, Pocket alerts and the optional notification listener. Opening that page requests no permissions. Camera waits for **Allow camera**. Bluetooth opens the native settings panel without requesting nearby-device access. Android still asks you to select Pocket for the default phone/SMS roles. Granting these roles permits access to sensitive call/message data. Existing native contacts, messages and calendars stay in Android's providers. Own tasks, notes, appointments, drafts, calculator history and clock entries are stored privately in the app; uninstalling removes those private entries. Export tasks/notes first if you need them elsewhere. User photos and ordinary native-provider messages remain separate from that private storage.

Files only opens Pocket Camera captures. On Android 10+, MediaStore ownership restricts reads to this app's published JPEGs under DCIM/Pocket, including owned captures from earlier Pocket versions. No photo-library permission is requested on those releases. On Android 6–9, new captures are kept in a private URI index; the previous last-photo link can be recovered when its path and EXIF identify Pocket. Earlier legacy captures beyond that last-photo link may not appear. The album shows the newest 2,000 photos in pages of 60. Photos removed from native storage disappear on Refresh. The first Files open after updating releases prior persisted file/folder grants and clears the old folder connection without deleting files. Arbitrary incoming image URIs are rejected before decoding. Received MMS attachments open a separate Messages viewer for image/text/PDF content and explicit sharing, not the Camera album.

**Notification access** is separate from the normal notification permission. The optional listener can see other apps' notification text, including banking notices and codes. It displays active notifications locally without automatically archiving received text; More → Make task explicitly saves the selected source with a task. Messaging-style notices show the latest available sender/text lines; duplicate group summaries are suppressed when child notices exist. Open uses the notifying app's action. Reply appears only for a freeform Android RemoteInput action and sends only after tapping Send. The current notification/conversation is rechecked before submission; expiry, a changed conversation, revoked access and a locked device block sending. Unfinished user-authored replies are stored privately for up to seven days and cleared after handoff; submission is not delivery confirmation. Android's restricted-settings warning for sideloaded APKs is expected. Open **notifs → Enable notification access** for the own setup page, then its button opens Android's component-specific consent screen where supported. If Restricted setting appears, use **Open app info → ⋮ → Allow restricted settings**, if offered by Android, then return and enable access. This is manual Android consent; Pocket cannot grant or bypass it. The page distinguishes off, approved-but-connecting, and connected states and requests a standard rebind only after access has already been approved. After connecting, Show test notification creates one local notice at the user's request. Open/Dismiss are 56 dp touch targets; ongoing notices cannot be dismissed. Leave this setting off if unwanted. Pocket's own message/alarm alerts use the normal **Allow notifications** permission. The SMS inbox separately needs Android's default-SMS role plus read permission. WhatsApp and other installed messaging apps need their own normal account/network and notification settings; receiving is independent of the launcher. The hub opens those apps for earlier conversations. It refreshes on return from settings, registers provider observers only after access is granted, and reports blocked-provider errors instead of treating them as an empty inbox. Existing SMS/MMS can be read; RCS/chat messages are not available through the SMS provider. Android can redact protected notification content; only currently active notices appear, not dismissed history.

There is no Internet permission or network SDK in the APK. SMS/MMS and calendar synchronization deliberately transfer data through Android services when those features are selected. There are no bundled ads, analytics or remote login credentials. The supplied APK retains the signing certificate used for the earlier Pocket versions, so it can update them without uninstalling.

## Verification

API 23/28/29/35 are represented across the automated suite. Native file/provider fixtures exercise capture ownership, stored JPEG bytes, album refresh/migration and rejection of unrelated images. SMS role, read-access return handling and provider errors are tested separately from notification listener consent/rebinding/connection/dismissal. Task migration, date ordering, subtasks, drafts/recreation, route Back, appointment draft recovery, readable timeline rows, native message opening/replies, stale-conversation guards, selected-line formatting, list continuation and actual Markwon rendering are checked. Native UI renders measure 56 dp notification/footer controls. The merged manifest retains no Internet, microphone, nearby-device or all-files access. The packaged `BUILD-STATUS.json` records results. These checks are not evidence of actual carrier delivery, Nothing OS permission consent or a full ROM boot.

For everyday Home use during verification, keep the current phone/SMS apps as Android defaults and assign them to Pocket's tiles by holding each tile. Keep stock Clock for essential alarms until Pocket is checked overnight. The custom Phone/SMS/Clock implementation is available for testing but is not handset-validated for daily reliance yet.

No Nothing Phone (3a) is connected to the build environment. Before using Phone or Messages as everyday defaults, check outgoing/incoming calls, speaker/mute/hold, both SIMs if present, multipart SMS and actual carrier MMS. Also check alarms with the display off, after reboot and through overnight battery management; camera capture/front/flash; a real calendar update; Camera-only album; notification restricted-settings consent; brightness/DND/Bluetooth; and bottom-edge Home/Recents/Back transitions. The full custom ROM remains a source integration kit with no compiled or flashable system image.
